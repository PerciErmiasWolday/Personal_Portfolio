## Problem

I was studying whether a neural network could learn the relationship between a classical system's motion and its quantum behavior. The simulations produced useful results, but comparing them meant going back and forth between notebooks, running code, and interpreting plots.

I wanted a way to explore those relationships visually, including the cases where the model's predictions didn't match the actual quantum simulation.

## Approach

I built Correspond around three things: running real physics simulations, generating machine learning predictions, and comparing their results.

I started with the harmonic oscillator, where classical and quantum behavior are expected to agree closely, then added fluxonium, a superconducting circuit where the relationship is more complicated.

Instead of showing only a prediction, I designed the interface so users could change parameters and compare the classical, quantum, and neural network outputs. This also meant the model's mistakes would be visible rather than hidden.

## Architecture

I built the frontend with React, TypeScript, and Plotly.js for interactive controls and visualizations. It communicates with a Python/FastAPI backend that validates user inputs and routes requests to the appropriate computation modules.

The backend uses SciPy and NumPy for classical simulations, QuTiP and scqubits for quantum simulations, and PyTorch for neural network predictions.

I kept model training separate from the live application. Python scripts generate paired simulation data, train and evaluate the models, and save checkpoints. When someone uses the website, the backend loads those trained models for inference rather than retraining them.

I also included source labels so users can distinguish live simulations, cached results, example data, and model predictions.

## Results

Correspond became a working research application supporting two physical systems, interactive parameter exploration, and side-by-side comparisons of classical, quantum, and predicted behavior.

The experiments also revealed important limits in what the neural network learned.

- **2 physical systems**: Harmonic oscillator and fluxonium
- **10 end-to-end user journeys**: Covered by Playwright tests
- **Fluxonium model**: Performed within roughly 2% RMSE of a simple mean-prediction baseline, showing it had not learned a meaningfully better mapping

Rather than hide the weak results, I included them in the research documentation and model evaluation. The application makes it possible to examine where the models work, where they struggle, and how their predictions compare with the underlying physics.

## What I learned

One of the biggest lessons was that building a working machine learning pipeline doesn't necessarily mean the model has learned something useful.

The harmonic oscillator gave me a way to check that the simulations and pipeline were behaving as expected. Fluxonium was harder. Its results pushed me to look more carefully at baselines, overfitting, and whether predictions were genuinely responding to changes in the input.

I also learned a lot about turning research code into software other people can interact with, from connecting the frontend and backend to handling simulation requests and making the results understandable.
